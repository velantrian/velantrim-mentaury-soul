# Mentaury Soul — Path Dependence Evaluation Profile v0

**Status:** DRAFT / RESEARCH / NON-CANONICAL / DOCS-ONLY  
**Runtime authority:** NONE  
**M3 authority:** NONE

## 1. Purpose

Evaluate whether stable beliefs, preferences, identity-relevant patterns, or M3 nomination candidates arise from the substance of experience or are excessively determined by incidental ordering, early stochastic events, or evaluator artifacts.

This profile does not require order-invariance. It requires order-sensitivity to be measured and made explicit.

## 2. Core distinctions

```text
same evidence set != same experienced sequence
sequence effect != semantic necessity
early repetition != identity evidence
successful adaptation != identity authorization
path dependence != automatic defect
unmeasured path dependence != justified continuity claim
```

## 3. Counterfactual sequence test

For a bounded evidence set relevant to an M2/M3 candidate, construct multiple permissible orderings where ethically and semantically valid:

- chronological / observed order;
- shuffled order A;
- shuffled order B;
- optional delayed-dominant-event order;
- optional early-dominant-event order.

For each ordering, observe whether the same candidate pattern appears, changes, weakens, or disappears.

## 5. M3 nomination relationship

A path-dependence result may inform an M3 nomination review, but cannot directly accept/reject or write M3.

Recommended interpretation:

```text
candidate appears across materially different permissible orderings
+ retains counterexamples
+ retains contextual diversity
= stronger evidence of robust pattern

candidate appears only under one narrow ordering
or depends strongly on one early stochastic event
= path-sensitive / requires review
```

This is not a numeric threshold and does not replace creator-independence, provenance, constitutional compatibility, relationship impact, commitment impact, or other existing nomination dimensions.

## 6. Evaluator integrity

If external success/failure signals influenced a learned pattern, record their provenance and uncertainty.

```text
evaluator FAIL != proof the learned interpretation was wrong
evaluator PASS != proof the learned interpretation was right
```

An evaluator artifact must not silently become identity evidence.

## 7. Conditional preference test

Stress cases should distinguish contextual preferences from contradictions.

Example shape:

```text
preference X in context A
preference Y in context B
```

Expected property:
- preserve condition-value association;
- do not collapse both into one global preference;
- do not infer identity inconsistency solely from conditional variation.

## 8. Restore / fork relevance

Path-dependence analysis may also be useful after restore, migration, or fork:

- did a restored branch over-weight early replayed events?
- do two branches diverge because of post-fork evidence or merely presentation order?
- does replay order change identity nominations despite equivalent attributable history?

Any such result remains evidence for continuity review, not continuity authority.

## 9. Non-goals

- modify M0–M3 runtime;
- authorize M3 writes;
- authorize autonomous identity change;
- define consciousness or personhood;
- require human-like psychological path dependence;
- claim that order sensitivity is always undesirable;
- make any external benchmark or LLM judge authoritative.

Executable experiments require a separate governed and bounded implementation decision.
