# 🔍 Mentaury Soul — Review Guide

## Minimal route

1. Read `AGENTS.md` → `docs/ai/README.md` → `docs/ai/project_manifest.json` → `docs/state/project_state.json` → `docs/CURRENT_STATUS.md` → `docs/GOVERNANCE.md`.
2. Resolve live GitHub main, open PRs and exact CI before treating a dated checkpoint as current.
3. Bound the task to one domain: provenance/claims, beliefs, Non-Projection, relations, identity, character, capability/privacy or runtime/action authority.
4. Follow `current state → owning contract → implementation → consumers → tests → CI/review`.
5. Check semantic distinctions such as `claim != belief`, `relation != truth`, `character != evidence`, `contract freeze != runtime authority`.
6. Use `README.md` and `SYSTEM_OVERVIEW.md` only when conceptual/human context is materially needed; they are orientation, not a mandatory engineering loop.
7. Classify documentation impact as `STRUCTURAL_CHANGE`, `STATE_CHANGE` or `EVIDENCE_ONLY`.
8. Preserve historical checkpoints and provenance.
9. Read back every affected maintained surface after edits; include the landing layer only when the change materially affects its assigned meaning.

Do not load the whole repository unless focused evidence is insufficient.
