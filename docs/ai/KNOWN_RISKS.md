# ⚠️ Mentaury Soul — Known Risks for AI Maintainers

This file is a compact orientation list. `docs/CURRENT_STATUS.md` and owning contracts remain authoritative for exact engineering state.

## KR-01 — Documentation drift

The repository historically had detailed milestone documentation without a first-class AI navigation layer. New work must keep README, SYSTEM_OVERVIEW, AI context, machine state and current status consistent without duplicating volatile evidence everywhere.

## KR-02 — Projection by documentation

Human/model-origin material can be accidentally described as SELF, belief or identity. Documentation must preserve attribution and Non-Projection boundaries.

## KR-03 — Relation/truth collapse

Typed relations are representational structure, not epistemic support or truth. Graph topology, relation count or relation vocabulary must not be described as evidence authority.

## KR-04 — Readiness/authority collapse

`READY`, frozen contract, implemented bounded component, green CI and Owner GO are distinct states. Never infer runtime/action/deployment authority from any earlier state.

## KR-05 — Visual duplication drift

Tree, mindmap, ASCII flow, tables and commentary have different semantic roles. Copying the same content into every representation creates multiple stale surfaces.

## KR-06 — Machine-state staleness

`docs/state/project_state.json` is a maintained snapshot, not an evergreen live-head claim. Live GitHub and `docs/CURRENT_STATUS.md` must be re-read before action.
